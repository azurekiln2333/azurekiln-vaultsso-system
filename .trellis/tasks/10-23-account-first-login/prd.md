# Account-first login, mailbox verification and complete user imports

## Goal

Let users identify their account before password entry and complete the appropriate password, mailbox and configured factor steps before login. Passwordless users reach first-password setup or administrator guidance without a dummy password. Administrators can import complete files with optional mailboxes and inspect distinct per-row results.

## Background

- `views/auth/login.html:63` and `:71` require account and password together. `server.js:2688` rejects an empty submitted password before lookup; `server.js:2711` returns `403 auth.password.not_set` for an empty or null stored password.
- `public/js/pages/auth/login.js:358` handles that error by opening recovery and only pre-fills email when the entered account contains `@`. Mail is sent separately through `/api/email-verification/send`, and `/api/password-reset` verifies the code before changing the password and returning to login.
- Main-site and OAuth login share `/oauth2/authorize`. Its existing `check_verification` path requires a valid supplied password, so it cannot discover an account's password state.
- Provider-created accounts may have an `@users.invalid` placeholder email. Such addresses cannot serve as this flow's recovery destination.
- The user authorized task creation and planning, requested the four existing right-side Herdr Pi agents, then explicitly selected manual code sending and the contact-administrator fallback.
- The workspace contains pre-existing uncommitted admin/MFA code and browser tests. These edits belong to other work and must be preserved.
